# Phase 6 Results: SMK2 Callout and the Shape line additions

Resolve Studio 21.1.0.14, Windows. Project `SMK Phase6 Gate` (your `SMK Test` was not touched). Scripting only, no UI automation. The macro was pasted fresh in every comp. One comp per check (a check with several cases uses several comps named after it), each with a Note above the graph and explicit node positions (Note y −3; Background x 0; macro x 4; Merge x 8; MediaOut x 12; one row per instance). `FlowView.Select()` before every paste, `Comp.FrameFormat.Rate` set to the timeline rate (and the comp frame size set for 1080×1920 and 4K), background changed by 0.001 before every timed render, `SaveProject()`. Comps are 24 fps and 120 frames unless the name says otherwise.

**Generator change (one line, described under L2):** `build/make_macros.py` — the leader (`UIC_Leader`) gets `InFade=0.0` and `OutFade=0.0`. Without it the end dot sat at the card edge from frame 0 and stayed on the last frame. Tests after the change: macros 112 passed, animator 10, cursor 13 + 27, fuse harness 12, motion rig 9, shape 47, core 49, text expressions 62, all 0 failed (kernel parity: skipped, no C compiler here). Evidence is in `docs/phase6_evidence/` (helper scripts `h8.py`, `cal.py`, `l13b.py`).

Defaults of the macro: card 0.3 × 0.15 of frame width at (0.5, 0.5) (576 × 288 px at 1080p, x 672–1248); Line Start (0.65, 0.5) = the card's right edge; Target (0.82, 0.28); thickness 3 px; dot radius 7 px; Line Draw Time 0.45 s; card In Delay 0, In Duration 0.5 s, In Engine Spring; Out Duration 0.5 s. The leader draws from `In Delay + 0.6 × In Duration` (0.3 s = frame 7.2) for the Line Draw Time (to 0.75 s = frame 18) and un-draws with the card's Out.
