## Findings and notes

1. **Per-timeline frame rate is not passed to the comp.** After setting a timeline to 60 fps with `useCustomSettings`, `comp:GetPrefs("Comp.FrameFormat.Rate")` stayed at 24. The seconds-based Fuses then ran 2.5 times fast (Index 4 with Stagger 0.05 started 4 frames after Index 0 instead of 12). I set `Comp.FrameFormat.Rate` to 60 on the two benchmark comps and the stagger became correct (frame 13 for Index 4). The project-level frame rate cannot be changed once timelines exist (`SetSetting` returned False). This comes from how Resolve sets up the comp, not from the macros, but it applies to every seconds-based SMK node. Worth a doc note.
2. P2 early-frame measurement: my first sweep sampler used a fixed circle centre and gave false low readings on frames 1–4. The ring slides in from the left during those frames. Re-centring on the ring's bounding box fixed it.
3. Colour controls: Label Color, Progress Color and Track Color all show as swatches. The Red/Green/Blue(/Alpha) rows below each swatch are shown expanded in the Inspector. Through the scripting API the Label Color's green and blue inputs are named "Green 1" and "Blue 1" (cosmetic, not visible in the Inspector).
4. The Inspector shows nothing for tools inside an expanded macro group (see P12).
