# Phase 4b Results: SMK Text, chain version

Resolve Studio 21.1.0.14, Windows. Project `SMK Phase4b Gate` (your `SMK Test` was not touched). Scripting only, no UI automation. The macros were pasted fresh from the freshly installed `Macros/SMK2/*.setting` into every comp. One comp per check, named after the check, each with a Note above the graph and explicit node positions (Note y −3; Background x 0; macro group x 4; Merge x 8; MediaOut x 12; one row per instance). `FlowView.Select()` before every paste, `Comp.FrameFormat.Rate` set to the timeline rate, background changed by 0.001 before every timed render, `SaveProject()`.
Comps are 24 fps and 120 frames unless the name or text says otherwise (`Z6_*` and `Z9_*` set their own rate).
`build/make_macros.py` was **not changed**: no generator fix was needed. Scripts: `docs/phase4_evidence/h6.py`, `z4meas.py`, `z4row.py`, `z4whole.py`.

## Things to know

- **Line macro Out (Z4):** with the default Line stagger of 0.15 s per character and the character-count compensation, the line-level slide and scale of a 13-character line finishes about 44 frames (1.8 s at 24 fps) before the clip end, while the letters keep fading one by one until the last frame. The gate text says the last word/line "leaves slightly early (documented, safe)"; for the Line macro this is not slight and it reads as the whole line sliding away first. The Word macro is milder (about 1 to 8 frames at the default stagger). I did not change the generator; a fix would be to base the Out start for word/line macros on the unit count and the units' first-character indices instead of the character count, or to take the per-character fade out of the Word and Line macros.
- Opacity only exists per character, so the Word and Line macros still fade letter by letter (also seen in W4).
- The opacity input is limited to 1, so overshooting engines do not push alpha above 1 (Z5).
- Z4's per-unit numbers for the Word and Line macros use a band around the text row, which the unit's own slide can leave; where that matters I also give the whole-row figures (all gone at frame 118).
