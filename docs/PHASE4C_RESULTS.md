# Phase 4c Results: SMK Text Word / Line Out timing and per-unit stagger

Resolve Studio 21.1.0.14, Windows. Project `SMK Phase4c Gate` (your `SMK Test` was not touched). Scripting only, no UI automation. Macros pasted fresh in every comp. One comp per check, each with a Note above the graph and explicit node positions (Note y −3; Background x 0; macro group x 4; Merge x 8; MediaOut x 12; one row per instance). `FlowView.Select()` before every paste, `Comp.FrameFormat.Rate` set to the timeline rate, background changed by 0.001 before every timed render, `SaveProject()`. Comps are 24 fps and 120 frames unless the name says otherwise.
`build/make_macros.py` was **not changed**. Scripts: `docs/phase4_evidence/h7.py`, `q23.py`, `q23m.py`.

## How "motion" and "alpha" were measured

- **Motion** (slide of the unit): in the `*Motion` comps Opacity At Start is 1, so nothing fades and only the slide shows. Words slide vertically and I follow each word's vertical centroid; lines slide sideways (Slide Angle 0) and I follow each line's horizontal centroid. "In starts" is the first frame the unit leaves its start offset; "In finishes" is the first frame it is within 1 px of rest; "Out starts" is the first frame after the hold that it is more than 1 px from rest; "Out finishes" is the first frame it is within 2% of its full start offset. Slide Distance 0.03 (58 px).
- **Alpha**: in the `*Out` comps all settings are default (the fade is per character), and I follow the brightest pixel inside the unit's box. For Word the box is the word's x range with a ±40 px row band widened by 70 px for the slide; for Line the box is the line's band, with Slide Distance 0 so the band does not move.

## Summary of the fix

The unit-level motion is fixed: the last word or line now finishes its slide and scale at frame 118–119 in every case I measured (Word: 118, 118, 118, 119; Line: 118, 118, 118, 119), and Stagger is now a per-unit time that scales as intended.
What is not fixed is the last-frame alpha. Because Opacity exists only per character, the letters after the first one in the last unit lag the unit's motion by up to (characters − 1) × the per-character delay, so the last letters of the last word or line are still visible on the last frame (alpha 0.03–0.09 for the last word, 0.24–0.35 for the last line). If a hard zero on the last frame is required, the Out start would also need to account for the last unit's length, or the clip's last frame would need to be allowed for.

## Not verified

- Q2 and Q3 numbers are for the measured texts only; the effect of other fonts and sizes on the per-unit alpha lag was not tested.
- Per-word alpha for a multi-line text on the Word macro was not measured.
